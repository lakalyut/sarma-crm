# «Пульс» — CRM для аналитики продаж

Внутренняя CRM для аналитики продаж кальянных табаков: импорт продаж из XLSX,
сопоставление сырых номенклатур со справочником товаров, аналитика по клиентам/городам,
ABC-рейтинг ассортимента, амбассадорские отчёты.

Подробности архитектуры и решений — [CLAUDE.md](CLAUDE.md).

## Возможности

- Авторизация пользователей (роли admin / user / ambassador), самодельный auth без сторонних фреймворков
- Импорт продаж из XLSX с нечётким сопоставлением номенклатуры (rapidfuzz)
- Аналитика по клиентам, городам, регионам — таблицы, графики, гэп-анализ ABC
- ABC-рейтинг ассортимента (ручная простановка категорий)
- Амбассадорские отчёты — SKU-статусы (New/Lost/Unstable) по клиентам
- Амбассадорские визиты — запись визита с анкетой (SKU на полке, цель, комментарий),
  история заметок по точке, лидерборд; вход через браузер и Telegram мини-апп
- Лента событий импортов, справочник регионов (город → макро-регион)

## Стек

- FastAPI, SQLAlchemy, Alembic
- Jinja2 + ванильный CSS/JS, без фронтенд-сборки
- Pandas + rapidfuzz (импорт и сопоставление номенклатуры)
- SQLite (dev) / Postgres (prod)
- Docker Compose (prod: db/web/nginx/certbot)

## Запуск локально (Windows/venv)

```powershell
python -m venv venv
venv\Scripts\pip.exe install -r requirements.txt

copy .env.example .env
# отредактировать .env — задать ADMIN_EMAIL/ADMIN_PASSWORD

venv\Scripts\alembic.exe upgrade head
venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8001
```

Приложение поднимется на `http://localhost:8001`. Логин — email/пароль из `.env`
(`ensure_admin()` при старте создаёт или чинит этого пользователя автоматически).

Тесты, форматирование, линт — см. раздел Commands в [CLAUDE.md](CLAUDE.md).

## Прод

Postgres + Docker Compose (`docker-compose.yml`). Деплой — push в `main` с зелёным CI
(GitHub Actions) автоматически триггерит выкладку на VPS по SSH. Подробности — раздел
Deploy в [CLAUDE.md](CLAUDE.md).

### Реальные визиты для роли user

В карточке пользователя администратор может включить **Запись реальных визитов**.
Роль `user` и доступ к аналитике сохраняются; визиты доступны во всех городах,
в Telegram и браузере, и учитываются в лидерборде. Без разрешения форма визита
в Telegram остаётся демонстрационной, браузерная запись недоступна. Для роли
`ambassador` реальные визиты доступны автоматически только в своём городе.
Отзыв разрешения не удаляет историю визитов, но исключает пользователя из
лидерборда, как и отключение пользователя. Перезапуск мини-аппа обновляет
подпись демо-режима; решение о записи всегда проверяется сервером.

### Клиенты в Telegram: ассортимент A/B/C

В мини-аппе список клиентов показывает число разных заказанных SKU из активного
ABC-ассортимента. Сегмент определяется по типу точки тем же правилом, что в
веб-аналитике. По умолчанию выбран последний месяц с продажами данного города;
доступен диапазон месяцев. Русские и ISO-значения одного месяца объединяются.
Клиенты без заказов за период остаются в списке с нулевым покрытием.
В детализации — карточка «Ассортимент по ABC»: счётчики A/B/C и списки
непокупаемых за выбранный период ароматов (бренд — аромат). Категория A
раскрыта сразу; B и C раскрываются отдельно. Полностью закупленная категория
показывается сообщением. SKU без рейтинга учитываются отдельно в списке клиентов.
Это анализ заказов, а не подтверждение наличия на полке. Расчёт выполняется
через SQL-агрегацию, без загрузки отдельных продаж для каждого клиента.

### Уведомления об обновлениях в Telegram

Для выпуска с объявлением добавьте запись в `release_updates.json`: уникальный
`key`, `title` и `body` (заголовок и текст вместе — максимум 4096 символов).
После успешного CI и проверки запущенного приложения деплой выполняет
`python -m app.release_updates`: создаёт черновики, не отправляя сообщений.
Повторный деплой не создаёт дубли и не перезаписывает правки администратора.

В админке **Обновления** (`/admin/updates`) можно изменить текст, сохранить
предпросмотр, выбрать аудиторию и отправить объявление. По умолчанию — все
активные пользователи бота с ролями `user` и `ambassador` и включёнными
уведомлениями. Старые пользователи получают сообщение по `telegram_id`;
после обращения к боту сохраняется ID личного чата. Если бот никогда не
запускался или заблокирован, результат отправки отражается как ошибка.
Команда `/updates` и кнопка под объявлением управляют подпиской.

Очередь и результаты хранятся в БД; отправка идёт отдельным потоком через
существующий Telegram-релей, максимум 10 сообщений/секунду. Поток включается
вместе с ботом (`TELEGRAM_POLLING_ENABLED=1` и `TELEGRAM_TOKEN`). Нужен ровно
один процесс приложения, как в текущем Dockerfile. После перезапуска
сообщения в очереди продолжают отправляться. Сообщения, отправка которых
прервана без подтверждения Telegram, получают статус «Доставка не подтверждена»
и не повторяются: Bot API не поддерживает ключи идемпотентности.
Кнопка повторной отправки обрабатывает только явные ошибки; доставленные и
неподтверждённые сообщения не затрагивает.
