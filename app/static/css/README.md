# Интерфейс «Пульса»

Общие значения находятся в `tokens.css`. Его подключают браузерная версия,
Telegram mini-app и автономные HTML-отчёты. Не копировать палитру в шаблоны.

## Компоненты

- Фон страницы — `--bg-page`, карточки — `--surface`, вторичный текст — `--text-muted`.
- `--primary` — заливка основного действия; `--primary-text` — ссылки и текст на светлом фоне.
- Радиусы: карточки 16 px, поля/кнопки 10 px, метки 6 px.
- Поля белые с рамкой `--input-border`; высота 42 px, на телефоне 44 px.
- Кнопки: основная `.btn`, дополнительная `.btn-secondary`, удаление `.btn-danger`.
  Опасное действие сохраняет явное подтверждение на уровне формы.
- ABC: A зелёный, B янтарный, C нейтральный. NEW — отдельная фиолетовая метка.
  Буква/текст обязательны: цвет не заменяет смысл. Каталоговый ABC и расчётный ABC
  по весу — разные показатели; показывать период и метод рядом с результатом.
- Тени использовать для выпадающих панелей, не для каждой вложенной карточки.
- Шаг отступов: 4/8/12/16/24/32 px. Основной текст 14 px, заголовок страницы 24 px,
  подписи 12–13 px. Поля ввода на телефоне 16 px для предотвращения zoom Safari.

## Поведение и состояния

Фокус — контрастная обводка 2 px с отступом 3 px. Поддерживать hover, disabled,
ошибку и ожидание ответа, учитывать `prefers-reduced-motion`. Ошибка должна
объяснять следующий шаг; нельзя обозначать её только цветом.

`custom_select.js` оставляет нативный select для отправки формы. Стрелки/Home/End
выбирают вариант, Enter подтверждает, Escape закрывает. Внешние изменения значения
должны сопровождаться `change`; если нужно обновить только отображение — `display-sync`.
При изменении списка вариантов/disabled компонент обновляется автоматически.
Мультиселект открывается Enter/Space, ArrowDown переводит фокус к чекбоксам,
Escape возвращает его на кнопку. Поиск с подсказками работает стрелками и Enter.
При нажатии на нефокусируемый пункт/метку предотвращать стандартный `mousedown`,
чтобы `focusout` не закрывал меню раньше `click`. Не отменять `touchstart`/`pointerdown`:
прокрутка касанием должна оставаться нативной. Чекбоксам и кнопкам внутри меню
разрешать получать фокус. Браузерные тесты покрывают мышь и касания по пункту
и по краю метки, а также закрытие снаружи и управление клавиатурой.
Все поля связывать с label через for/id; для иконок задавать доступное имя.

## Клиенты

На широком экране — таблица, до 768 px — карточки из тех же строк DOM.
Чекбоксы, поиск и сортировка общие; выбранные клиенты сохраняются при поиске.
Переход к своду/амбассадорскому отчёту переносит выбранных клиентов, город и месяцы.
Фильтры на телефоне свернуты при открытии; сводка показывает три основных значения
(два на 320 px), остальные раскрываются кнопкой «Все показатели».
Нажатие заголовка количества/веса/SKU выбирает показатель динамики и сортирует список.
Повторные нажатия переключают убывание → возрастание → исходный порядок.
На телефоне эти заголовки доступны над карточками. Δ сравнивает последний месяц
с данными со средним за предыдущие месяцы с данными внутри выбранного периода.

## Проверка

Проверять 320/390/768/1440 px: отсутствие прокрутки всей страницы по горизонтали,
длинные названия, пустые результаты, загрузку/ошибку, выбор для отчётов, клавиатуру.
Широкие аналитические таблицы могут прокручиваться внутри своего контейнера.
Проверить мини-апп, браузер и скачанный HTML без сети.

Браузерные регрессии (Chromium):

```sh
pip install -r requirements-browser.txt
python -m playwright install chromium
RUN_BROWSER_TESTS=1 DATABASE_URL=sqlite:////tmp/pulse-ui-tests.db TELEGRAM_POLLING_ENABLED=0 PYTHONPATH=. pytest -q tests/test_ui_browser.py
```

Тесты используют только отдельную тестовую БД, синтетические продажи и TestClient;
внешние Telegram-запросы не выполняются. График в этих тестах заменён заглушкой;
визуальные проверки графиков проводить с настоящим Chart.js. Отдельно проверить
реальные Telegram/iOS/Android перед оценкой полной доступности продукта.
